Read Ramabana history

Ramabana appends each finished turn to ~/.config/ramabana/agent-history.jsonl, one JSON object per line. A turn holds the prompt, the reply, the session it belongs to, and an activity list with one row per tool call: the tool’s name, its arguments, the result in detail, and ok for whether it succeeded. A result longer than 600 characters is kept whole in <cfg>/<log>-details/<session>.jsonl, and the row keeps its start and a details reference. read_history reads the file and puts those results back whole through Ramabana’s hydrate_turns, so a row written before Ramabana 0.2.59 reads as it always did, and tool_args returns a call’s arguments as a dict even when the row stored them as JSON text.

Assess a route

A route is the sequence of tool calls a turn made. assess_turn checks it for six kinds of problem and returns an Assessment: a score that starts at 100 and loses 20 points per Finding, the number of calls, and the findings themselves. A route is marked down when:

  • the request names GitHub and FOSSICK but the first research call is something other than fossick read-gh-repo (route),
  • a tool could not decode the arguments it was sent (schema),
  • a shell command does what a dedicated tool does (bypass),
  • a shell command fails with a usage error (tool_protocol); a test that really fails is not one,
  • a call that already failed is repeated with the same arguments (repeat_failure),
  • a call the person refused is made again instead of asking them (denial_retry).

assess_history assesses several turns together, and each of its findings records the turn it came from.

bypass_tool names the dedicated tool a shell command stands in for, or returns None. It splits the command at &&, ||, ; and newlines, ignoring those inside quotes and heredoc bodies, and looks at the part of each piece before any |. Every piece must map to a tool, because a piece with no tool needed the shell anyway, and the answer is the first piece’s tool. cd pieces, env and VAR=value prefixes, and git’s global options (-C, -c, --no-pager) are ignored. A command that ends in & maps to the background runner, run_shell_bg. When offered is given, a tool outside it gives None.

Some calls need a person’s approval. A refusal is recorded as a failed row of kind ask, or as a failed row whose detail starts with Denied by human operator. denial_reason returns the reason the person gave, 'no reason given' when there is none, and None for a row that is not a refusal. A refusal on its own is not a tool failure and earns no finding. Making the same call again instead of asking the person is a denial_retry, whether it happens later in the same turn or in the next turn of the same session when the reply in between asked no question.

Build the warm start

A warm start is chat history made from accepted rounds, placed in front of a new chat so the model sees good tool use first. warm_start builds it in Urai’s message format from the user’s library in ROUNDS_DIR and the seeds packaged with dhrona in SEEDS_DIR. When you pass the tools you offer, a round is replayed only if every recorded call still binds to the offered tool’s signature. Rounds are sorted by meta.rank, lower first and 50 when it is missing, and then rounds recorded on model come first. The sort is stable, so a library round comes before a seed of equal rank. limit keeps the first few, 2 by default. Rishi re-exports the same chat format, so any Rishi backend can continue this history through messages=, and prepare_chat puts the warm start into an empty chat object.

call_valid checks one call by binding its arguments to the tool’s signature. inspect.signature follows functools.wraps and accepts any keyword for a **kwargs parameter, so wrapped and permissive tools pass. round_valid checks every call in a round, and misfit says why a round does not fit.

import functools
def run_shell(command, cwd='.', timeout=60): ...
def grep(pattern, **kw): ...
@functools.wraps(run_shell)
def wrapped(*a, **k): return run_shell(*a, **k)
assert call_valid({'command': 'ls'}, run_shell) and not call_valid({}, run_shell)
assert not call_valid({'command': 'ls', 'bogus': 1}, run_shell)
assert call_valid({'pattern': 'x', 'anything': 1}, grep) and call_valid({'command': 'ls'}, wrapped)

The approval-refused seed shows the right response to a refused write: the assistant names the refused action and asks one question instead of trying again. Its calls bind to shalya’s view_file(path, start, end) and replace_text(path, edits), so it is replayed only when those tools are offered. The other seeds each teach one route on the shalya 0.1.0 and ramabana 0.2.0 tool set. git-flow uses the git tools, and its commit result carries an undo token. search-choice picks between semantic search, literal search and a listing. notebook-edit edits notebook cells by id. memory-key shows that a note saved under an existing key replaces the old one, and delegation confirms a sub-agent’s report by reading the lines it cites. Every seed has a rank, so a small limit still picks the most useful lessons.
